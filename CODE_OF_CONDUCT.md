# Code of Conduct

## Purpose

AXOS is a correctness-critical system: it exists so that autonomous
execution can be trusted. The community around it is held to the same
standard — evidence over assertion, honesty over comfort, and respect
for the people doing the work.

## Expected behavior

- Be precise and honest about what is proven, what is tested, what is
  blocked, and what is unknown. Do not overstate results.
- Critique ideas and evidence, not people. A failing audit or a
  blocked proof is a finding to record accurately, not a fault to
  assign.
- Give credit: cite the evidence, reports, and prior work you build
  on.
- Keep discussions focused and professional. Assume good faith until
  there is clear reason not to.

## Unacceptable behavior

- Harassment, intimidation, discrimination, or personal attacks in any
  form.
- Publishing another person's private information without consent.
- Misrepresenting verification status — for example, relabeling a
  blocked proof as complete, or presenting unexecuted tests as
  evidence.
- Submitting secrets, credentials, or personal data to the repository
  (see SECURITY.md).
- Bad-faith contributions: plagiarized work, fabricated test results,
  or deliberately weakened safety properties.

## Scope

This code applies in all project spaces: the repository, issue
trackers, pull requests, and any official communication channels.

## Enforcement

Violations can be reported privately through GitHub's private
vulnerability reporting channel for this repository, or by contacting
the repository owner directly. Reports are handled confidentially.

Consequences scale with severity and history: a private warning,
temporary restriction from participation, or a permanent ban from the
project. Maintainers' enforcement decisions are final for the spaces
they administer.
